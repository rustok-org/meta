## 1. Прецеденты: закрытое ядро — это мейнстрим

| Проект | Что даёт | Как решает дистрибуцию |
|---|---|---|
| **Tailscale** | VPN-mesh; открытый демон, закрытый control plane | Universal `curl\|sh`: весь скрипт в `main()`, вызываемой последней строкой (обрыв скачивания не исполнит пол-скрипта); детект 40+ дистрибутивов через `/etc/os-release`; ставит подписанные пакетные репы, не сырые бинари; macOS → просто открывает App Store; Windows скриптом не покрыт |
| **1Password CLI** | Полностью закрытый бинарь | Никакого universal-скрипта: нативные менеджеры per-платформа — brew (mac), winget (Win), свои GPG-подписанные apt/rpm-репы (Linux) |
| **ngrok** | Закрытый агент | Ровно 3 канала на Linux: apt-репа на S3 + Snap + прямой Download; сборки из исходников нет как класса; Docker — первоклассный таб |
| **Bun** | Открытый, но канал показателен | Один `curl\|sh` вход; на Windows прозрачно передаёт эстафету `irm bun.sh/install.ps1\|iex`; критика: качает бинарь без чексумм |
| **LND** | Lightning-нода | Онбординг: 24 слова печатаются прямо в терминал под ручную запись — терминальный сид-онбординг = индустриальная норма |

**Наше преимущество на фоне критики curl|sh:** наш install-скрипт не качает бинарей — только
оркеструет docker-команды; целостность образа гарантирует registry по digest.

## 2. MCP-каналы (для Docker-упакованного MCP-сервера)

- **MCPB (.mcpb, экс-.dxt) — НЕ ПОДХОДИТ.** Спека поддерживает ровно 4 типа: node/python/binary/uv;
  слово «docker» в 762-строчном MANIFEST.md — 0 раз; `entry_point` обязан быть файлом внутри
  архива, валидатор проверяет физическое существование. Проверено 3-0 тремя независимыми
  верификаторами (github.com/modelcontextprotocol/mcpb). Идея «обернуть docker run в .mcpb»
  похоронена. Заодно: миф «.mcpb = скачал-кликнул» верификация тоже убила (0-3).
- **Docker MCP Catalog/Toolkit — канонический дом.** 300+ верифицированных серверов
  контейнерами (versioning/provenance/подписи, docs.docker.com); ценность Toolkit —
  «настрой один раз, подключи все клиенты» (Claude Desktop/Cursor/Claude Code) вместо ручного
  JSON в каждом. **Наш PR уже подан: docker/mcp-registry#4259** (ждёт ревью Docker).
  Открытый вопрос: совместимость нашего two-window (`docker exec … rustok-console`)
  с запуском через Toolkit-гейтвей.

## 3. Инсайт Капитана: агенты живут в Docker

Наш stdio-способ (клиент спавнит `docker run -i`) работает только с хост-приложений
(Claude Desktop/Cursor). Агент, живущий в контейнере (n8n/Dify/Flowise/compose-стеки/сендбоксы),
не может сделать `docker run` без docker.sock — а дать агенту docker.sock = крах всей модели
(прочтёт volume, exec'нется в консоль). **Для контейнеризованных агентов мы сегодня
неустановимы.** Решение — демон-режим + compose-блок: кошелёк как сервис-сосед в docker-сети,
агент ходит по HTTP/SSE с capability-токеном. Фундамент уже в репо: `sse.py`, `auth.py`,
capability-гейт на connect. Бонус: правило двух окон из этикета становится структурной
гарантией — у агента в контейнере нет docker CLI физически.

## 4. ClawHub: форматы и цена простоты

Топ-авторы качества: **@steipete** (2.2M загрузок на 60 скиллов; Github 193k, Gog 189k),
**@tezatezaz** (clawcast: скриптовый диалоговый онбординг, ClawAudit-бейдж),
**@iahmadzain/@al-one** (вершина коннектор-формата: home-assistant 21.6k; mcp-hass 5.4k
с декларативной установкой в манифесте). Топ платформы — промпт-скиллы (self-improving agent
467k) — другой жанр.

Три формата скиллов:
1. **Промпт-скиллы** (инструкции без бинарей) — топ по загрузкам, не наш жанр.
2. **Самоустанавливающиеся тул-скиллы** — скилл ставит себя руками агента:
   - `evm-wallet` @surfer77 (3.9k, топ-кошелёк): агент сам `git clone`+`npm install`+setup;
     человек не открывает терминал. Цена: приватный ключ плоским файлом доступен агенту,
     «спроси подтверждение» — чистый этикет.
   - `clawcast` @tezatezaz (2.7k): нумерованные скрипты 01→06, цикл «вопрос → скрипт →
     подтверждение». Цена: пароль и мнемоника проходят через чат агента.
3. **Коннекторы к сервису** (`home-assistant` 21.6k): сервис уже стоит у юзера,
   установка = env/конфиг + токен из UI сервиса.

**Доминирующий паттерн успеха: «агент устанавливает всё сам, человек не трогает терминал».**
Кошельки-лидеры покупают простоту, отдавая агенту ключи.

**Наш формат** — гибрид 2+3, единственный на площадке: «коннектор к self-hosted сервису,
где сервис ставится вместе со скиллом, а секретная часть онбординга — принципиально
human-only». Это и уникальность (агент не может увести деньги даже при prompt-injection),
и трение (бейзлайн: наш листинг 791 загрузка против 3.9k у evm-wallet).

Механики, которые стоит перенять (не ломая тезис): декларативные `requires`/`install`
в манифесте (mcp-hass); readiness-скрипт каждую сессию (clawcast `check_wallet.sh`);
ClawAudit-бейдж; запись скилла в TOOLS.md воркспейса; диалоговый онбординг «один вопрос
за раз»; keyword в тайтле (наше правило discoverability).
