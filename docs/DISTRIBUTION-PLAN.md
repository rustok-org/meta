> §3 (позиционирование линейки) — ПРЕДЛОЖЕНИЕ, ждёт ратификации.
> Факт-база: `DISTRIBUTION-RESEARCH-2026-07.md` (рядом). Контекст продуктов:
> core `.claude/decisions/2026-07-10-two-products-naming.md`, NORTH-STAR.

## 1. Принятые решения (и почему)

### 1.1 rustok-core остаётся приватным навсегда
**Решение Капитана 2026-07-11.** Публичный РЕПОЗИТОРИЙ = раскрытие проприетарных исходников
ядра — противоречит модели «исходники приватные, наружу только бинари» (прецеденты: Tailscale
control plane, ngrok, 1Password). Следствия: CI-путь `wallet-publish` не используется;
канонический путь сборки wallet-образов = **podman с dev-машины** (креды есть, проверено
0.5.0 и 0.6.0). Опция на будущее БЕЗ раскрытия чего-либо: GHCR «Manage Actions access» пакета
rustok-core → read для rustok-org/mcp (включит CI-сборку, оставив и репо, и пакет приватными).

### 1.2 MCPB (.mcpb) не делаем
Формат не поддерживает docker (4 типа: node/python/binary/uv; «docker» в спеке 0 раз;
entry_point обязан существовать внутри архива — верифицировано 3-0). Обёртка `docker run`
в .mcpb = хак против контракта формата. Пересмотр — только если спека добавит container-тип.

### 1.3 Главный retail-канал — Docker MCP Catalog/Toolkit
Причина: наша аудитория хост-клиентов (Claude Desktop/Cursor) и так обязана иметь Docker
для нашего образа; Toolkit убирает самый болезненный шаг — ручной JSON в каждом клиенте
(«настрой один раз, подключи все клиенты»). PR docker/mcp-registry#4259 подан — дожимать.
⚠️ Проверить: как two-window (`docker exec … rustok-console`) живёт при запуске контейнера
Toolkit-гейтвеем (имя контейнера, volume, lifetime) — до анонса канала.

### 1.4 ClawHub tui-листинг — в модели «агент ставит всё, человеку — один секретный шаг»
Причина: доминирующий паттерн успеха на ClawHub — самоустановка руками агента (evm-wallet
3.9k против наших 791); но лидеры платят за это ключами у агента. Мы забираем их UX,
НЕ отдавая ключи: агент сам делает все несекретные шаги (проверка docker → pull → volume →
генерация keyring-пароля скриптом сразу в 0600-файл, не видя его → health-check → TOOLS.md),
человеку остаётся ровно одно действие — `create-wallet` в СВОЁМ терминале (12 слов + PIN).
Перенять: декларативные requires/install в манифесте, readiness-скрипт каждой сессии,
ClawAudit-бейдж, keyword «Ethereum» в title. Позиционирование против соседей — прямо в
SKILL.md: «у них агент владеет ключом; у нас prompt-injection не может увести деньги —
один human-шаг и есть цена этой гарантии».

### 1.5 install.sh довести до Tailscale-стандарта (второй канал)
`main()`-обёртка (обрыв не исполнит пол-скрипта); детект docker/podman; «нет Docker → ссылка
на Docker Desktop»; печать готового MCP-JSON + опциональный `--configure claude`; парный
`install.ps1` для Windows (Bun-паттерн: sh передаёт эстафету PowerShell). Наш скрипт не
качает бинарей (образ по digest из registry) — критика curl|sh к нам почти не липнет,
проговорить это в доках.

### 1.6 Демон-режим + compose-канал — арка после Этапа 6 (инсайт Капитана)
Причина: агенты почти всегда живут в Docker; из контейнера наш stdio-способ недоступен
(нужен docker.sock = крах модели безопасности) → **контейнеризованные агенты сегодня
неустановимы — дыра покрытия**. Решение: кошелёк как long-lived сервис-сосед в docker-сети,
агент ходит по HTTP/SSE с capability-токеном; установка = ~10 строк в существующий
compose.yaml юзера. Фундамент готов: sse.py, auth.py, capability-гейт. Бонус безопасности:
у агента в контейнере физически нет docker CLI — правило двух окон из этикета становится
структурной гарантией. Демон-режим уже помечен в спеке slice1b §8 как отдельная арка —
теперь у неё продуктовое обоснование, не только удобство. Скоуп арки: long-lived режим
entrypoint, модель выдачи агентских токенов (не loopback-минт), пересмотр сетевого
hardening (остаточный MITM из Р3), healthcheck, compose-канон в доках.

### 1.7 Нативные brew/winget-пакеты кошелька — не делаем
Нечего ставить нативно — всё в образе; отдельная поверхность поддержки для маленькой
команды. Пересмотр — если родится host-native console / нативные бинари (v2-опция спеки).

## 2. Порядок работ (рекомендация Инженера)

1. **Этап 6** (E2E pty-приёмка + podman-tmpfs + upgrade-доки) — закрывает текущую арку slice1b.
2. **Круг «tui-листинг»** (§1.4 + §1.5): степ-скрипты + переписанный SKILL.md + манифест +
   install.sh/ps1. После него — ops листингов (ClawHub/MCP Registry/Smithery, образ 0.6.0
   уже в GHCR).
3. **Арка «демон-режим + compose»** (§1.6) — отдельная спека, свой круг гейтов.
4. Параллельно ops: дожать docker/mcp-registry#4259 (+ Toolkit-проверка из §1.3).

## 3. Линейка продуктов — «лестница доверия» (РАТИФИЦИРОВАНО Капитаном 2026-07-11)

Сегодня: №1 rustok-wallet (агентский, 0.4.x, execute_send намеренно) · №2 rustok-wallet-tui
(0.6.x, human-approval через консоль) · mobile (в разработке: телефон = подписант,
device-initiated провод, Этапы 2/4 mobile-арки; по NORTH-STAR канал одобрений для удалённых
юзеров = приложение, не чат).

Предложение: НЕ объединять код; объединить НАРРАТИВ — один бренд, одна ось
«сколько контроля отдать агенту», три ступени:

| Ступень | Ключ | Кнопка одобрения | Аудитория |
|---|---|---|---|
| №1 агентский | у агента | нет (полная автономия) | удалённые юзеры (агент через Telegram и т.п.), которым ручное подтверждение физически недоступно |
| №2 tui | рядом с агентом (контейнер) | человек, консоль на том же хосте | power-user за компьютером |
| mobile (курс NORTH-STAR) | на телефоне человека | человек, телефон — откуда угодно | конечная форма: агент вообще без ключей (F3) |

Почему лестница, а не три продукта-конкурента: ступени не каннибалят друг друга, а образуют
апгрейд-путь (начал с №1 на $20 → перерос в №2 → mobile для серьёзных сумм); одна таблица
на сайте/README объясняет всё позиционирование; mobile становится флагманом тезиса
(«агент предлагает — телефон подписывает»), console остаётся pro/server-нишей (headless,
VPS, локальный контроль), №1 — честной «горячей» ступенью с дисклеймером. Console и mobile
НЕ конкурируют: это два канала одобрения одной архитектуры (локальный и удалённый).

**Нюанс ступени 1 (Капитан, при ратификации):** №1 существует не для «любителей риска»,
а для юзеров, общающихся с агентом удалённо (Telegram и т.п.), которым ручное подтверждение
физически недоступно — канала пока не существует. Поэтому №1 даёт все возможности без
ограничений, честно. Когда mobile приедет, он закроет именно эту дыру (удалённая кнопка) —
№1 останется для тех, кто осознанно выбирает полную автономию агента.

### Задача: сайт rustokwallet.com под лестницу (поручение Капитана 2026-07-11)
Обновить контент под три ступени + переделать Hero визуально: идея Капитана — три окна/карточки
(клик → подробности по ступени), «или креативнее». Кандидат-концепция от Инженера: три живых
«окна» интерфейсов — чат с агентом (Telegram) · терминал консоли с картой транзакции ·
телефон с push-подтверждением — каждое кликабельно в свою ступень. Отдельный круг:
найти исходник сайта → контент-план → макет Hero → добро Капитана → вёрстка.
